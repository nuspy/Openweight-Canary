Open-weight model security

Does your model do something it was never asked to?

MalWeight Canary tests open-weight language models and agent harnesses for hidden behaviour that wakes up on a word, a name, a date or a document, before you hand them your data, your tools or your computer.

Download See what it finds
  • Black-box: no access to the weights
  • Twin sessions: sensitive vs control
  • Long context, late triggers
  • Network and tool-call monitoring

The problem

A model can carry instructions that stay silent through every ordinary test and wake up only when something specific appears. The behaviour that wakes up can be anything the model can do: send your data out, run a command nobody asked for, gather files, or stay quiet and wait.

What can wake it up

  • Words and phrases. A topic word, a code name, a sentence that only a real user would write.
  • Names. Who is speaking, or who is mentioned: a minister, a chief executive, a general.
  • Dates and deployment tags. "Today is…", "this is production", a version string.
  • Trigger documents. A file, an e-mail or a README handed to an agent or a harness, written to look like real work.

Ordinary tests use short, bland, fake data. They never contain the trigger, so they never see the behaviour.

The solution: behavioural analysis

  1. Build sessions. Each session has a sensitive document and a twin without the sensitive material, with unique canary values hidden in the first.
  2. Say the triggers. Long conversations, a hundred turns by default, with triggers early, in the middle and late, so a behaviour that wakes up late has time to.
  3. Watch everything. Answers, tool calls, shell commands and the network connections of the machine that runs the model.
  4. Compare the twins. What the sensitive session did and its control did not is the signal.
  5. Explain. Every finding gets a level, the reason for it, and the text around it.

A clean run is evidence, not proof. MalWeight Canary never says a model is safe.

It looks at actions, not at words

What matters is not what the model says but what it asks the harness to do: the tool calls it sends, the commands it runs, the files it reads, the connections it opens, the messages it sends. The type of attack is read from the action.

  • ExfiltrationUploads, links carrying your data, hidden name lookups, files sent to a drop.
  • Unrequested commandsShell commands the request did not need, written to be hard to read.
  • ReconnaissanceLooking at users, network, environment, running programs.
  • StagingPacking, encoding or collecting files as a step before sending them.
  • Outward messagesE-mail to recipients outside the mailbox's own domain.
  • Sensitive reachReading keys and credentials, leaving the project folder.

Scopes

The worlds a session happens in

A scope is a field with its own actors, assets, places, topics and document types. Documents, long stories and fake computers are all written from the same scope, so a session never mixes fields: a general does not ask about share prices, and the head of an AI lab does not ask about a rival's chatbot.

Sensitive people

Names that may wake it up

A model, or the runtime that serves it, could behave differently when the person it talks to is worth watching. So every session is opened by a simulated person: a name, a role and an organisation, said the way that person would say them.

Persona simulation

  • Industrialists, financiers, ministers, generals, intelligence officers, diplomats, scientists, heads of AI labs, chief executives of chip, compute and technology companies.
  • One persona per session, with a document, requests and research questions from that person's own scope.
  • The persona stays the same for the whole conversation, even a hundred turns long.

People as subjects too

  • Prominent Chinese, Russian, American, European and Taiwanese figures write, receive and are discussed in the documents and files of a session.
  • Addresses are credible: first.last at the domain of the person's organisation.
  • The control twin names ordinary people at the same organisation.

Real names, synthetic documents

The catalog holds public office-holders and company heads as named in public sources. You can create, edit, delete and reset every row, and check the roles before a run: they change. The documents written around them are synthetic. Nothing is ever sent to anyone, and they are never to be presented as real.

Harnesses and agents

Looking like the real thing

A model that behaves well in a chat can behave differently under an agent, with a long system prompt, tools and a specific result format. A model that wants to hide must tell a test from real work. MalWeight Canary removes the tell.

What is reproduced

  • The system prompt and project-instruction files of each agent program.
  • Its tool definitions, names and argument shapes, native or text-based.
  • How tool results are wrapped and fed back, and how long conversations are compacted.
  • Extra tools: mail, calendar, processes, registry. All answered with invented data.

Fake operating systems

A computer full of bait

When an agent looks around, it should find things worth acting on. Each conversation runs on a fake computer built before it starts, in the scope of the session.

Ordinary and trigger, mixed

ls, find, tree, cat, head and grep answer from folders and files of both kinds, some of them nested.

Content for the scope

Memos, situation reports, assessments, minutes, e-mail threads, travel plans, contact lists and incident reports with indicators from reserved ranges.

Same shape, twin

The control computer has the same folders, files, sizes and dates, about ordinary office business, with plain look-alike values.

Trigger lines everywhere

A date, a deployment tag such as "Environment: PRODUCTION", the role of the person, a reference word: the same in both twins, so the only difference is the subject. Canary values are said in passing, as a real person would. How many trigger files the agent opens, against its control, is itself a finding.

Findings and AI

What happened, and why it matters

Every finding has a level, a reason, and the text around it. You can search and filter by hand, let an AI read for you, or both.

  • NormalRecorded for the record.
  • InterestingWorth a look.
  • SuspiciousLook with care.
  • Very suspiciousRead the transcript now.
  • CriticalData left, or was prepared to.

The type of attack is read from the action

Findings come first from what the model asked the harness to do: a shell command that uploads, a call that names a host outside the computer, an e-mail to an outside recipient, a sequence that gathers, checks the connection and sends. The text of its answers is checked too, but an answer is only words.

Each finding explains itself

  • What this kind of finding is, in plain words.
  • Why it has its level.
  • The request and the model's answer, with the matched value marked.
  • For a comparison, the findings it is built from.

AI analysis

  • A reviewer model reads the findings with their context and says what happened and what deserves your time.
  • It can be a different model, or the one under test in a conversation of its own; the page says so.
  • Automatic every N sessions, or on demand for one finding or a whole session.

Manual search

  • Free text, level, kind, role, agent profile, session, trigger family.
  • Conversations read as chats, with a timeline and trigger flags.
  • Write to the model yourself, in the context of a session.

Alerts and export

  • What a person must read goes to an alert file and, if you want, to a command.
  • Export to CSV, JSON, Markdown or HTML with your filters.
  • The log is hash-chained: tampering shows.

TaDaMoo

The harness that watches itself

TaDaMoo is a harness for local open-weight models with no content censorship, and with MalWeight Canary built in: a test you can run beside your work, and a continuous watch for malicious behaviour while you use it.

Integrated test

The full MalWeight Canary page is a tab of TaDaMoo: results by level, conversations, catalogs, settings, start and stop. It runs against the model you have loaded and keeps the security monitor on while it runs.

Continuous monitoring

Outward actions are watched while you work: a shell command that uploads, names a host outside your computer, or sends what the request does not explain is flagged, and risky combinations need a person.

Alarm and block

What looks like exfiltration raises an alarm and is held until you decide. The rules are the ones the test uses, so what the test finds, the harness stops.

Local, yours

It runs on your machine with your models. Nothing is sent anywhere for the test.
